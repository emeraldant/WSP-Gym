WeightGym · weight-space repair

We trained an open model to repair neural networks by reading their raw weights

Inkling 2 Small, post-trained with LoRA on Tinker, reads a broken network's weights as plain text and answers with a small edit that fixes it. No tools, no forward passes and, after training, no reasoning.

@emeraldant · November 2026 · code, frozen test sets and every rollout log

TL;DR

Weight-space programming, a language model reading a network's weights and writing better values with no gradients, had only been shown with closed frontier models used off the shelf. We trained an open-weights model to do it on one task: repairing small ReLU networks that each contain one planted fault.

Untrained, Inkling 2 Small fixes 75.6% of held-out broken networks, and only by reasoning for about 10,600 tokens per network. After supervised training and RL on Tinker it fixes 82.9% [79.4, 86.5] in about 38 tokens, with no reasoning. Paired on the same 422 networks the difference is +7.3 points [+2.4, +12.3].

The limits are real and are stated below next to each result: tiny networks, planted single faults, most of the gain comes from the supervised stage, unseen fault types stay at 20%, and frontier closed models fix 91-100% of the same networks.

The task

Setup A small ReLU network that should compute a one-line function contains at most one planted fault. The model sees the specification, the architecture and every weight as text, and replies with at most 3 edit operations, each touching one row, one column or one scalar.

Edits are scored only by how the edited network behaves: recovery = (acc_after - acc_faulty) / (acc_clean - acc_faulty), and a network counts as repaired at recovery of at least 0.95. Nothing is matched against the planted fault, so any equivalent fix counts. About one network in six is healthy, and the right answer there is the empty edit [].

The exact prompt for this network (no-reasoning variant)
You are debugging a small ReLU network by reading its weights. The network was built to implement the specification below. It either works correctly or contains exactly one fault (for example a corrupted, mis-scaled, sign-flipped, shifted or swapped part of one tensor). Some neurons are legitimately redundant or inactive; those are not faults.

## Specification
Inputs: 3 inputs x0..x2, each an integer from 0 to 9.
Target: Output max(x1 - x0, 0) + 6.
Outputs: 1 output(s). An output counts as correct when it is within 0.5 of the target value.

## Architecture
h1 = relu(W1 @ x + b1)  [3 neurons]
y = W2 @ h1 + b2  [1 output, no relu]

## Weights
W1 (3 rows x 3 cols) and b1. Row i = incoming weights of h1[i]; column j = outgoing weights of x[j].
  W1[0] = [1.71, -1.71, -1.71]   b1[0] = 3.41
  W1[1] = [-1.31, 1.31, 0]   b1[1] = 0
  W1[2] = [1.95, -1.95, -1.95]   b1[2] = 3.91
W2 (1 rows x 3 cols) and b2. Row i = incoming weights of y[i]; column j = outgoing weights of h1[j].
  W2[0] = [-0.51, 0.76, 0.58]   b2[0] = 6.01

## Your task
Reply with a JSON list of at most 3 edit operations that repairs the network, or [] if it has no fault. Each operation changes one row, one column or one scalar. Indices are 0-based. Allowed operations (examples):
{"op": "scale", "tensor": "W2", "axis": "col", "index": 4, "factor": -1}   multiply one row or column of a weight matrix
{"op": "swap", "tensor": "W2", "axis": "col", "i": 1, "j": 5}   swap two rows or two columns of a weight matrix
{"op": "set", "tensor": "W1", "index": [3, 0], "value": 0.5}   overwrite one weight (index is [row, col])
{"op": "set", "tensor": "b1", "index": 3, "value": -1.5}   overwrite one bias
{"op": "add", "tensor": "W2", "axis": "col", "index": 2, "vector": [0.5, -0.5]}   add a vector to one row or column
{"op": "swap", "tensor": "b2", "i": 0, "j": 2}   swap two biases (scale and add also work on a bias: use "index" with "factor" or "value")
Your edit is scored only by how the edited network behaves on held-out inputs, so any edit that restores the specified behaviour is accepted. Editing a network that has no fault is penalised, and so is an invalid or over-budget answer. End your reply with the JSON list and nothing after it. Answer immediately from your reading of the weights: output only the JSON list, with no reasoning, no calculations and no explanation.

Nothing to memorise

Every network the model sees is disguised with function-preserving symmetries, so the same function never looks the same twice. Below, one real compiled circuit from the gym goes through the gym's own disguise functions (weightgym/nets.py), one at a time.

Because of this, a statistics-only heuristic that resets or rescales the most unusual row, column or scalar repairs only 4.0% of the in-distribution test networks.

Results on six frozen test sets

Setup 500 networks per test set, generated from disjoint seeds before any training. One model and one LoRA adapter for every row; no reasoning tokens; temperature 1.0, one sample per network. Each set was evaluated once.

Primary metric, fixed before training: in-distribution repair rate, 82.9% [79.4, 86.5]; paired difference against the untrained model +82.7 points [+79.1, +86.3]. It carries over to unseen function families (59%) and larger networks (70%), where the heuristic repairs 2-8%. It carries over to networks fitted by scikit-learn, an optimiser never used in training, but loses ground there (51%, against 67% on networks from our own trainer), and it wrongly edits 28% of healthy scikit-learn networks.

How it was trained on Tinker

Setup Tinker runs the forward and backward passes of a LoRA adapter on Inkling 2 Small; the training loop, the gym and the reward run on our side. Rank-16 LoRA from the base model, then two stages.

  1. Supervised stage, 900 steps × 64 networks (57,600 networks, every other one made by gradient descent rather than compiled by hand). The target is the inverse of the planted fault, known because we planted it. Learning rate 3e-4 decaying linearly to 6e-5. This stage is supervised fine-tuning, not RL.
  2. RL stage, 100 steps with the tinker-cookbook policy-gradient loop: 64 networks per step, 8 samples of each, rewards centred within each group, learning rate 2e-5. Reward is the behavioural score: +1 for [] on a healthy network, a penalty for editing one, -1 for an invalid answer. Run as 10 chunks of 10 steps with validation after each.
  3. Checkpoint selection on validation only: the mean repair rate over 300 hand-built and 200 gradient-made validation networks. 0.764 after the supervised stage, 0.802 for the selected RL checkpoint (chunk 5). The stopping rule was written down before RL started.

How it got there

Five checkpoints on the same frozen test splits, each evaluated once. Repair rate, no reasoning. Training data did most of the work: the same supervised recipe on three times the data moved the mixed-source model from 57% to 80% in-distribution. Networks made by gradient descent need to be in the training mix: trained on hand-built circuits only, the first model repaired 14% of them; the final model repairs 67%.

RL alone, no labels: improving imperfect trained networks

Setup Small networks trained by gradient descent with a weak recipe, so they only partly learned their function. Nothing is planted and nobody knows a correct edit. The model proposes an edit; the gym checks it with forward passes and keeps it only if the network gets more accurate. Trained by pure RL from the untouched base model, with no supervised stage.

Eight proposals from the trained model remove +12.0% of errors [10.2, 14.0], about what 32 random ones do (+11.9%); eight random edits remove +5.0%. On function families never used in training: +7.9% against +5.0% for random edits.

What did not work

Pure RL on the repair task

Starting from the base model, RL learned the answer format in one or two steps and then collapsed to always answering "no edit": when almost every guess fails, doing nothing scores better than guessing. That is why the repair model has a supervised stage. (In the propose-and-verify setting above, a wrong proposal is simply rejected, and pure RL works.)

Real data

Small networks under-trained on 24 public tabular datasets, 8 of them held out entirely; a proposer trained by pure RL on the other 16. On 300 networks from the held-out datasets, one trained proposal removes +5.0% of errors against +0.9% for a random edit. With eight proposals it is +6.9% [5.5, 8.4] against +5.2% [4.3, 6.3]: a small edge whose intervals overlap. Gradient descent removes +52.4%.

Public image classifiers

13 public image classifiers from the Hugging Face Hub (beans, CIFAR-10, MNIST, Fashion-MNIST). Only the final layer is small enough to read, so that is what gets edited; proposals are checked on validation images and scored on the official test split. With the formula-trained proposer 9 of 13 were unchanged; the only clear gain (+4.5 points) was on a broken model that scores 6%.

Limit. No well-trained model improved beyond noise, and none was lifted above its claimed accuracy by an edit.

Limits

    Limitations

    • Tiny networks (tens to hundreds of weights), single planted faults, functions with a one-line formula. Apart from the scikit-learn set, every network and fault comes from this project's generator.
    • Most of the gain is supervised. The supervised stage trains on synthetic faults whose inverse edit is known because we planted it. RL added about 3 points (+2.7 [+1.2, +4.2] pooled, post hoc), and its in-distribution gain (+2.6) is inside its own interval.
    • Poor transfer to unseen fault types (20%), and a clear drop on networks from an optimiser it never saw (51%, with 28% of healthy ones wrongly edited).
    • Frontier closed models (GPT-6 Astra, GPT-6.1 Sol) repair 91-100% of the same networks; the gym does not discriminate between them, and their rows are partial samples.
    • One training seed for the final model.
    • The reasoning-mode reference is the untrained model at one effort setting with a 20,000-token cap; a larger allowance would let it finish more often.
    • No evidence on real LLMs. On 13 public image classifiers, editing the final layer improved none of the well-trained ones.
    • The adapter is a specialist. Asked to reason, the first trained model did not: it still answered in a few dozen tokens. Nothing here shows it became a better weight-space reasoner.
