WeightGym · weight-space repair

We trained an open model to repair neural networks by reading their raw weights

Inkling 2 Small, post-trained with LoRA on Tinker, reads a broken network's weights as plain text and answers with a small edit that fixes it. No tools, no forward passes and, after training, no reasoning.

{{byline}} · November 2026 · code, frozen test sets and every rollout log

TL;DR

Weight-space programming, a language model reading a network's weights and writing better values with no gradients, had only been shown with closed frontier models used off the shelf. We trained an open-weights model to do it on one task: repairing small ReLU networks that each contain one planted fault.

Untrained, Inkling 2 Small fixes {{think_id}} of held-out broken networks, and only by reasoning for about {{think_tokens}} tokens per network. After supervised training and RL on Tinker it fixes {{rl_id}} {{rl_id_ci}} in about {{rl_tokens}} tokens, with no reasoning. Paired on the same {{vs_think_n}} networks the difference is {{vs_think}} points {{vs_think_ci}}.

The limits are real and are stated below next to each result: tiny networks, planted single faults, most of the gain comes from the supervised stage, unseen fault types stay at {{faults_0}}, and frontier closed models fix {{frontier_range}} of the same networks.

The task

Setup A small ReLU network that should compute a one-line function contains at most one planted fault. The model sees the specification, the architecture and every weight as text, and replies with at most 3 edit operations, each touching one row, one column or one scalar.

Edits are scored only by how the edited network behaves: recovery = (acc_after - acc_faulty) / (acc_clean - acc_faulty), and a network counts as repaired at recovery of at least {{repair_threshold}}. Nothing is matched against the planted fault, so any equivalent fix counts. About one network in six is healthy, and the right answer there is the empty edit [].

Nothing to memorise

Every network the model sees is disguised with function-preserving symmetries, so the same function never looks the same twice. Below, one real compiled circuit from the gym goes through the gym's own disguise functions (weightgym/nets.py), one at a time.

Because of this, a statistics-only heuristic that resets or rescales the most unusual row, column or scalar repairs only {{outlier_id}} of the in-distribution test networks.

How it was trained on Tinker

Setup Tinker runs the forward and backward passes of a LoRA adapter on Inkling 2 Small; the training loop, the gym and the reward run on our side. Rank-{{rank}} LoRA from the base model, then two stages.

  1. Supervised stage, {{sft_steps}} steps × {{batch}} networks ({{sft_nets}} networks, every other one made by gradient descent rather than compiled by hand). The target is the inverse of the planted fault, known because we planted it. Learning rate {{sft_lr}} decaying linearly to {{sft_lr_end}}. This stage is supervised fine-tuning, not RL.
  2. RL stage, {{rl_steps}} steps with the tinker-cookbook policy-gradient loop: {{rl_groups}} networks per step, {{rl_group}} samples of each, rewards centred within each group, learning rate {{rl_lr}}. Reward is the behavioural score: +1 for [] on a healthy network, a penalty for editing one, -1 for an invalid answer. Run as {{rl_chunks}} chunks of {{rl_chunk_steps}} steps with validation after each.
  3. Checkpoint selection on validation only: the mean repair rate over 300 hand-built and 200 gradient-made validation networks. {{sft_score}} after the supervised stage, {{sel_score}} for the selected RL checkpoint (chunk {{sel_chunk}}). The stopping rule was written down before RL started.

How it got there

Five checkpoints on the same frozen test splits, each evaluated once. Repair rate, no reasoning. Training data did most of the work: the same supervised recipe on three times the data moved the mixed-source model from {{mixed_id_0}} to {{scale_sft_id_0}} in-distribution. Networks made by gradient descent need to be in the training mix: trained on hand-built circuits only, the first model repaired {{first_trained_0}} of them; the final model repairs {{rl_trained_0}}.

RL alone, no labels: improving imperfect trained networks

Setup Small networks trained by gradient descent with a weak recipe, so they only partly learned their function. Nothing is planted and nobody knows a correct edit. The model proposes an edit; the gym checks it with forward passes and keeps it only if the network gets more accurate. Trained by pure RL from the untouched base model, with no supervised stage.

What did not work

Pure RL on the repair task

Starting from the base model, RL learned the answer format in one or two steps and then collapsed to always answering "no edit": when almost every guess fails, doing nothing scores better than guessing. That is why the repair model has a supervised stage. (In the propose-and-verify setting above, a wrong proposal is simply rejected, and pure RL works.)

Real data

Small networks under-trained on 24 public tabular datasets, 8 of them held out entirely; a proposer trained by pure RL on the other 16. On {{real_n}} networks from the held-out datasets, one trained proposal removes {{real_rl1}} of errors against {{real_rand1}} for a random edit. With eight proposals it is {{real_rl8}} {{real_rl8_ci}} against {{real_rand8}} {{real_rand8_ci}}: a small edge whose intervals overlap. Gradient descent removes {{real_grad}}.

Public image classifiers

{{ih_n}} public image classifiers from the Hugging Face Hub (beans, CIFAR-10, MNIST, Fashion-MNIST). Only the final layer is small enough to read, so that is what gets edited; proposals are checked on validation images and scored on the official test split. With the formula-trained proposer {{ih_unchanged}} of {{ih_n}} were unchanged; the only clear gain ({{ih_best_change}} points) was on a broken model that scores {{ih_best_before}}.

Limits

    Limitations

    • Tiny networks (tens to hundreds of weights), single planted faults, functions with a one-line formula. Apart from the scikit-learn set, every network and fault comes from this project's generator.
    • Most of the gain is supervised. The supervised stage trains on synthetic faults whose inverse edit is known because we planted it. RL added about {{rl_gain_pooled_0}} points ({{rl_gain_pooled}} {{rl_gain_pooled_ci}} pooled, post hoc), and its in-distribution gain ({{rl_gain_id}}) is inside its own interval.
    • Poor transfer to unseen fault types ({{rl_faults_0}}), and a clear drop on networks from an optimiser it never saw ({{rl_external_0}}, with {{external_clean_bad}} of healthy ones wrongly edited).
    • Frontier closed models (GPT-6 Astra, GPT-6.1 Sol) repair {{frontier_range}} of the same networks; the gym does not discriminate between them, and their rows are partial samples.
    • One training seed for the final model.
    • The reasoning-mode reference is the untrained model at one effort setting with a {{think_cap_tokens}}-token cap; a larger allowance would let it finish more often.
    • No evidence on real LLMs. On {{ih_n}} public image classifiers, editing the final layer improved none of the well-trained ones.
    • The adapter is a specialist. Asked to reason, the first trained model did not: it still answered in a few dozen tokens. Nothing here shows it became a better weight-space reasoner.
