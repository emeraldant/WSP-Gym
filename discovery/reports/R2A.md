**Original query**: Test H4 (round_2/hypotheses.md): a non-LLM learned weight reader (gradient-boosted ranker over hand-designed weight/spec-only per-candidate features, trained only on freshly generated episodes at seeds disjoint from every split, plus a learned abstain/no-op head) gets within 10 points of scale_rl. PRIMARY: overall success (faulty repaired OR clean answered []) of the ranker's top-1 answer vs scale_rl on all 500 test_trained networks, paired bootstrap 95% CI. Secondary: test_id, test_external, test_larger, test_faults; compiled-only vs trained-only vs mixed training; feature importances; do ranker and scale_rl fail on the same networks.

**Methodology**
- Data and seeds. Fresh training episodes via `weightgym.env.make_episode` with `GymConfig(size=i%2, source=...)` and default families/faults: 8000 `source="trained"` episodes at seeds 70,000,000-70,007,999 and 8000 `source="compiled"` at 71,000,000-71,007,999. The generation script asserts these seed ranges are disjoint from the set of all 6,712 seeds found in data/*.jsonl (checked; ranges in the log `outputs/R2A/gen.log`). Training clean fraction 17.8% (trained) / 18.6% (compiled). Rate measurement: trained 0.17 s/episode generation (0.2 s with featurising and labelling), compiled 0.001 s. Total CPU for generation + featurising + labelling = 1,899 CPU-s (31.7 min), 2 worker processes (CPU-time guard at 35 min).
- Candidate space (generic, no generator scale factors 0.3/0.4/2.5/3.0): scale of any weight row, weight column or bias with factor in {-1, 0.5, 2}; swap of two columns of W2..WL; swap of two output units (row swap + bias swap, a 2-op candidate, needed for label_swap); set bias to 0; add to a bias +-{0.5,1,2} x mean |nonzero| of its incoming row; set one weight to 0, to -w, or to another distinct value found in the same row; add +-{0.5,1} x median|W| to every entry of a column of W2..WL. Mean 588 candidates per network (max 1604). Single answer = one candidate (max 2 ops). The candidate space cannot contain multi-op repairs, so it has an oracle ceiling (some candidate reaches recovery >= 0.95, or clean) of 94.2% on test_trained, 93.4% test_id, 94.0% test_external, 94.8% test_larger, 62.0% test_faults.
- Features (95 per candidate, weights/architecture/spec text only; no forward pass at test time): spec (family one-hot, n_in, n_out, output kind, depth, widths, n_weights, boolean vs integer input domain parsed from the input description); op descriptor (op type, factor, layer, last-layer flag, axis, #ops); neuron features of the affected hidden neuron (row norm and out-column norm relative to layer plus their ranks, log-gain robust z (rescaling-invariant), bias/row-norm, row/column sign sums and positive fractions, row-sign x column-sign, best cosine match among the layer's other rows, cosine of the matched neuron's out column, norm ratio to the match, cluster sign-consistency cos_row*cos_col, interval-arithmetic pre-activation bounds relative to row scale, dead / always-on flags from the input box, share of linearised path magnitude, sign of path vs net linearised output); candidate features (entry magnitude and robust z within row, duplicate-entry count, #distinct row values, new value and delta relative to row scale, line norm/rank, pair cosine, swap gain-outlier z before/after, linearised effective-map diagonal for output-unit swaps, etc.). Labels (training only) use forward passes: recovery >= 0.95 with the same accuracy function as `env.score_answer`.
- Ranker: sklearn HistGradientBoostingClassifier on candidate rows of faulty episodes (all positives + 30% of negatives, for memory), answer = argmax predicted probability. LightGBM was not installed (HGB + argmax is the allowed alternative). Hyperparameters (8-point grid over lr {0.05,0.1}, max_leaf_nodes {15,63}, l2 {0,1}, 300 iterations) chosen by top-1 repair rate on the matching validation split only: trained-only on data/val_trained.jsonl, compiled-only on data/val.jsonl, mixed on both pooled. Chosen for the primary arm: lr 0.1, 63 leaves, l2 1.0 (val_trained top-1 repair on faulty 37.3%).
- Abstain/no-op head: separate HGB classifier predicting "network is clean" from episode-level weight features (max |gain z|, number of gain outliers, min cluster consistency, dead / always-on counts, bias and entry outliers, linearised map magnitude, spec features) plus the ranker's top-3 scores, gap, entropy and candidate count (these ranker scores are 3-fold out-of-fold on the training set). Answer [] iff P(clean) > tau; tau chosen on the validation split to maximise overall success (primary arm tau 0.249, val overall 41.0%, abstain AUC 0.82 on val_trained). Head hyperparameters (4-point grid) chosen by validation AUC.
- Scoring: every top-1 answer was turned into JSON and scored by `env.score_answer`; label-based and score_answer successes agreed exactly (0 mismatches in all 15 split x arm cells). scale_rl = runs/final/scale_rl/<split>.jsonl, one sample per network, stored `success`. Bootstrap = 10,000 paired resamples over networks.
- Pre-registration: the primary arm is the trained-only ranker with abstain head on test_trained (all 500 incl. 97 clean). All other arms/splits/analyses are secondary. No test-split information was used for any choice. One run, no iteration on features after seeing test results.
- Scripts: discovery/experiments/scripts/R2A_{rate,feat,gen,splits,main,analyze}.py; outputs in discovery/experiments/outputs/R2A/ (gen.log, main.log, analyze.log, importance.json, eval.pkl); figure discovery/reports/figures/R2A_summary.png.

**Results**

PRIMARY (test_trained, n=500; 403 faulty, 97 clean): ranker (trained-only) overall success 40.2% [36.0, 44.4] vs scale_rl 72.2% [68.2, 76.2]. Paired difference -32.0 pts, 95% CI [-36.8, -27.2]. H4 (within 10 pts) is rejected; the CI excludes -10 by a wide margin. Breakdown: faulty repaired 33.0% (scale_rl 66.7%), clean answered [] 70.1% (scale_rl 94.8%). Without the abstain head (always answer top-1): 28.8% overall, 35.7% on faulty. Always-[] baseline 19.4%. Oracle ceiling of the candidate space 94.2%.

Observations: (i) every cell is far below scale_rl. (ii) Sharp source dependence: each single-source ranker only works on its own source (trained-only: 33% faulty repair on test_trained but 6.9% on test_id; compiled-only: 29.9% on test_id but 6.9% on test_trained); the mixed ranker is worse than the matched specialist on each (25.1 vs 33.0 on test_trained; 26.1 vs 29.9 on test_id) and its hyperparameter validation uses pooled val. (iii) The weight reader, unlike scale_rl, is not even close on compiled test_id where template structure is available.

Per fault (test_trained faulty; ranker trained-only / scale_rl / ceiling): bias_shift 37/60/90 (n=67); label_swap 5/95/100 (20); scale_out_col 21/62/77 (61); sign_flip_in 62/63/100 (71); sign_flip_out 37/82/100 (65); swap_out_cols 27/62/100 (66); weight_corrupt 15/62/85 (53). Only sign_flip_in is at parity. Per depth: 1 hidden layer 36% vs 73%; 2 hidden layers 21% vs 38%. Per family: ranker 23-40% in every family, scale_rl 38-90% (largest gaps argmax 35 vs 90, count 40 vs 90, compare 39 vs 84; smallest dnf 23 vs 44, equality 24 vs 38).

Do they fail on the same networks (test_trained)? Faulty only: both fail 114, ranker-only fail 156, scale_rl-only fail 20, both succeed 113; phi of failure indicators 0.27, kappa 0.22 (all 500: phi 0.31, kappa 0.25). Failures are only weakly correlated, but the ranker's failure set nearly contains scale_rl's (only 20 of 134 scale_rl failures are repaired by the ranker; 114 networks fail for both, i.e. 85% of scale_rl's faulty failures are also ranker failures simply because the ranker fails 70%). Union (success if either succeeds) on test_trained: 76.6% overall vs 72.2% for scale_rl alone (faulty 71.7% vs 66.7%). 29 of the ranker's 299 failures are outside its candidate space entirely. Other splits (faulty only, phi): test_external 0.25, test_id 0.02, test_larger 0.08, test_faults 0.03 (there the ranker fails nearly everywhere).

Feature importance (primary ranker, permutation on val_trained, drop in top-1 repair from a base of 0.373; 2 repeats): top single features nb_iv_lo_rel +0.20 (interval-arithmetic lower pre-activation bound of the affected neuron, relative to row scale), factor +0.17, delta_rel +0.13 (size of the proposed change relative to row scale), nb_iv_hi_rel +0.11, nb_bias_rel +0.09, entry_z +0.09, fam_argmax +0.07, entry_abs +0.06, nb_cn_rel +0.06. Group-level (permute the group jointly): neuron-level features +0.33, candidate/entry/pair features +0.32, op descriptor +0.24, spec +0.20, swap partner features +0.01. The interval-arithmetic features (dead / always-on neuron bounds) and bias-relative-to-row-scale carry the most signal, which fits bias_shift repair, and the delta/entry features carry weight_corrupt-style repairs; the cluster-consistency and sign features that H4 expected to find sign flips matter much less (nb_match_cos_col +0.03, nb_cluster_cons not in the top 25). Abstain head (val_trained AUC 0.82): dominated by m0_abs (magnitude of the linearised input-output map, +0.175 AUC) and the ranker's top-1 score (+0.127); then min cluster consistency +0.023.

**Interpretation**
- Strong negative result for H4. A tuned, hand-featurised gradient-boosted ranker with 16,000 fresh training networks reaches 40% overall on test_trained vs 72% for scale_rl (gap -32 pts, CI [-36.8,-27.2]); the pre-registered threshold was -10. The result is the same direction in all 15 secondary cells (gaps -15 to -80 pts). Its edge is smallest where the planted fault is a pure sign flip of an input row (sign_flip_in 62% vs 63%), a fault whose weight-only signature (sign inconsistency with similar neurons) a ranker can exploit, and absent for label_swap (5% vs 95%), swap_out_cols, sign_flip_out and weight_corrupt.
- What this says about scale_rl: its 72% is not reproducible by generic per-candidate statistics of the weights even though the candidate space contains a correct answer for 94% of networks; the model uses information (e.g. relation of the output units to the spec, which input matters for which output, interaction between layers) that the features here do not capture. It is also much more source-robust than the ranker, which collapses when the network source changes (33% -> 7%), and the trained-source ranker's reading of SGD networks does not transfer to compiled ones. Failures are only weakly correlated (kappa 0.22), so the two readers are largely complementary but not by a margin that helps much (union +4.4 pts).
- Caveats: (a) one feature design and one hyperparameter grid (8 points) with a single run; a stronger reader (spec-aware features such as the compiler template of R1C, pairwise/neuron-matching features, deeper search, LightGBM lambdarank, multi-op candidates) was not tried and the negative applies to this generic feature set. In particular H4 forbids generator factors, and several fault types (scale_out_col with 0.3/0.4/2.5/3.0, bias_shift delta U(1,4) units) are not exactly in the grid {-1,0.5,2}, so some of the ranker's failures are capped by the candidate grid (ceiling 77% for scale_out_col, 90% bias_shift, 85% weight_corrupt) but most of the 94%-ceiling gap is ranking, not coverage. (b) Negatives were subsampled to 30% and the abstain head's threshold tau was tuned on 200-300 validation networks; overall success on test_trained is sensitive to the abstain trade-off (no-abstain 28.8%, abstain 40.2%); validation overall was 41.0%, so no optimism was visible. (c) scale_rl is a single sample per network; stored success is used. (d) The input domain (0..1 vs 0..9) used in interval arithmetic is read from the prompt text; the candidate prior for set values uses row-contents only. (e) Failing-input variant episodes show failing inputs in the prompt; the ranker ignores them (using them would need forward passes).
- Follow-ups: (1) combine the ranker as a prior in a verify-then-search cascade (H1/H7 style) since it has 33% top-1 and presumably far higher top-k; top-k repair curves were not computed here. (2) Add the R1C template-based features to see how much of the test_id source gap is closed. (3) Per-fault specialised rankers; test whether features of the hidden-unit-to-output relation (spec-aware, e.g. which output corresponds to which input) close the label_swap/argmax gap.
