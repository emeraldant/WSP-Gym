**Original query**: Test H2 (pre-registered, checkpoints/round_1/hypotheses.md): is localisation the model's skill and op choice its bottleneck? For each FAILED faulty network of runs/final/scale_rl (test_id, test_trained, test_faults primary; test_larger, test_families secondary) build the model-indicated units, run a richer-op local search on them only, and compare repair share (recovery >= 0.95 via env.score_answer) against an equal-size random subset of a global pool with the SAME op family (paired, bootstrap CI). Also: evaluations needed, split by failure category (no-op separately; final_verify 8 samples as alternative unit source), held-out half-of-inputs check, and whether the story holds across splits especially unseen fault types.

**Methodology**
- Failures: scale_rl faulty networks with success=False, one sample each (n = 72 test_id, 134 test_trained, 326 test_faults, 125 test_larger, 167 test_families; 824 total). Scripts: discovery/experiments/scripts/R1B_search.py, R1B_analyze.py, R1B_extra.py; outputs discovery/experiments/outputs/R1B/ (res_*.jsonl, merged.csv, analysis.txt); figure discovery/reports/figures/R1B_local_vs_random.png.
- Unit = (matrix index l, row r) = neuron r produced by W_l (hidden or output); (-1,j) = input feature. Model-indicated units from the answer's ops: W row i -> unit (l,i); W col j -> (l-1,j); b_l[i] -> (l,i); set W[r,c] -> (l,r) and (l-1,c); swap -> both. A candidate edit is "local" if any unit it was generated from (its anchors) is indicated; each indicated unit's incoming row, bias and outgoing column are all in scope.
- Op family (identical for local and global pool; the local set is literally a filter of the global pool; every candidate = one op or, for swaps, optionally row-swap+bias-swap as one 2-op candidate): scale a row or column by F = {-1, +/-0.25, +/-1/3, +/-0.4, +/-0.5, +/-2, +/-2.5, +/-3, +/-10/3, +/-4}; zero a row/column/bias; set bias = b + d*u, u = mean nonzero |row|, d in +/-{0.5..4 step 0.5} (the "bias needed" grid); per-weight set to 0, -w, +/-row-median|w|; swap rows, swap bias, swap row+bias (output-row/label swap), swap columns, each with every other neuron in the layer; rank-1 `add` to the outgoing column of hidden neuron j: vector = alpha*u_C*v, u_C = median nonzero |W_{l+1}|, alpha in +/-{0.25,0.5,0.75,1,1.5}, v in {1} if fan_out=1 else {unit vectors e_k} plus the top-2 left singular vectors of the whole W_{l+1} (scaled to max-abs 1). This v is estimated from weights only; it is a crude guess and does NOT use the data. Global pool mean 1,649 candidates (range ~700-9,000).
- Repair test: recovery on the full scoring inputs from task.correct; the best local candidate was rechecked with env.score_answer (agreement 100%), and the planted inverse reproduces success on 824/824 (sanity).
- PRIMARY (as pre-registered): P(local set contains a repairing candidate) vs P(random subset of size |local set| drawn from the global pool contains one), computed EXACTLY by the hypergeometric formula from the number of repairing candidates in the fully evaluated global pool, paired per network, bootstrap over networks (4-5k resamples) for 95% CIs. Networks whose answer touches no unit (no-op or invalid) have an empty local set and count as local failures in the primary (so the primary is an intention-to-treat number); the edit-type-only numbers are reported separately. The test_families / test_larger rows are secondary.
- Alternative units (variant V): union of the units from scale_rl's answer plus its 8 final_verify samples (available only for test_id, test_trained; test_external is not in this task's splits). Oracle-localised (O): local set built from the planted units (uses ep.inverse_edit; analysis only, never used by the search).
- Held-out: input rows split 50/50 (per-seed permutation); the candidate is chosen by best accuracy on half A within the set; "repaired on A" = recovery on A >= 0.95 (A uses clean/faulty accuracy on A), "holds on B" = recovery on the untouched half B >= 0.95. Random baseline: 20 random equal-size subsets per network.
- Caveats up front: (i) F contains 10/3 and 1/3, 0.4, 2.5 which are the inverses of the fault generator's SCALE_FACTORS (0.3, 0.4, 2.5, 3); the grid is inside the user-specified range but this is knowledge of the fault family and helps scale faults equally in local and random sets. (ii) Candidates are scored on the same inputs used to define repair (selection = acceptance), except in the held-out analysis. (iii) Scoring domains are small for many families (16-128 inputs), so half-splits are coarse. (iv) Greedy depth-3 extension was run only on test_id/trained/faults and the first ~95 test_larger networks (time), none on test_families; it is exploratory.

Unseen fault types (test_faults). scale_in_row (n=135, 81% edit-type): local 0.719 [0.644,0.793] vs random 0.483, diff +0.236 [0.173,0.298]; among edit-type fails local 0.890 vs 0.598; when the answer touched the planted row (88) local repair is 100%. Oracle 1.00 and the global pool 1.00. This is the cleanest confirmation of "right unit, wrong op" (scale where a different factor is needed), but note the F grid includes the inverse generator factors. spurious_direction (n=191, 94% edit-type, 96% of those touch a planted neuron): local 0.377 [0.309,0.445] vs random 0.326, diff +0.051 [0.018,0.084]; oracle 0.408, global pool 0.455, baseline search 0.251. Here localisation is essentially solved but the op family fails: a single-op rank-1 add of weight-estimated direction cannot reproduce a 2-3 neuron shared-direction fault (the inverse is 2-3 `add` ops with neuron-specific amplitudes); 55% of these nets have no repairing candidate in the entire global pool at depth 1. The 0.38-0.45 that are repaired are mostly incidental (zeroing/scaling/swapping the touched columns). So for the unseen faults the localisation-vs-op story is real for scale_in_row and not testable with this op family for spurious_direction (the bottleneck is a multi-op, data-dependent magnitude/direction estimate, which my weights-only v does not provide).

Held-out half (selection on A, test on B): pooled over edit-type local sets (n=681): repaired on A 0.626, on A and B 0.586; P(holds on B | repaired on A) = 0.937 (n=426). By split P(B|A): 0.956 id, 0.879 trained, 0.908 faults, 1.000 larger, 0.975 families. Random equal-size subsets: A 0.484, A&B 0.436. Oracle sets: A 0.860, A&B 0.818, P(B|A)=0.952. So about 6% of local "repairs" are overfit to the selection half (more on test_trained, ~12%), but the local-vs-random gap survives held-out (0.586 vs 0.436, +15 pp).

Greedy depth <= 3 (exploratory, not pre-registered): for nets with non-empty units not repaired by one op, greedy local selection (best-accuracy candidate each stage, same indicated units) repairs an additional 0.346 [0.277,0.415] (n=188; 0.429 on test_faults n=119, mostly spurious_direction), 0.362 with V. The random-subset greedy comparator (0.54) is not comparable: it draws from the whole network each stage, so it can win at stage 1 on nets where the local set failed by definition (selection against local); I do not interpret it.

Op families that repair (local successes, n=420 nets): scale 250, swap 177, add 138, weight set 133, bias 88, zero 57 (a net can use several), consistent with many functional repairs per network.

**Interpretation**
- H2 is partly supported. Local search restricted to the units the model touched beats an equal-size random subset by +13-15 pp pooled (CI excludes 0; positive in test_id, test_trained, test_faults, test_larger), cuts the evaluated pool ~9x (first repair ~6.6x sooner), and the repairs hold on held-out inputs ~94% of the time. But "repairs most failures" is not supported: 51% overall, because 17% of failures give no unit at all (no-op/invalid) and ~30% touch the wrong units. The ceiling set by perfect localisation is 85% (oracle), so the localisation bottleneck is large, not just op choice.
- The mechanism is sharply conditional: if the answer touches the planted unit, the richer op family repairs 77% overall (95-100% on seen faults, scale_in_row 100%); if not, local search does worse than random (26% vs 46%). The "76% of unseen-fault failures are right unit wrong op" statement from round 0 is confirmed for scale_in_row (repairable) but for spurious_direction right-unit is not enough with single-op candidates (oracle 41%).
- test_families is a clear exception (diff -0.02): failures there are mostly mislocalised (57% don't touch a planted unit) -> localisation does not transfer to held-out families as well as op choice errors.
- No-op failures: no localisation; extra verify samples recover units for 10% (id) / 49% (trained) of them but do not repair better than random.
- Caveats: random-subset baseline is strong because the pools are small (~1.6k) and healthy slack gives many incidental repairs (random equal-size hits 28-50%); pool design knows the fault scale factors and is not a pre-registered fixed op grid across alternatives (no sensitivity analysis on F/DB/AL); local vs random difference is on per-network expected hit probability, not a single draw; held-out halves are coarse on 16-64-input domains; greedy covered only part of the data. Follow-ups: (1) multi-op / data-fitted add (least-squares column delta on hidden activations) for spurious_direction; (2) ranking local candidates by model-implied op (use the model's own op as a prior) to cut evaluations below 45; (3) a cascade where the model's own ops decide local vs global (fall back to global when no unit or the model's edit leaves accuracy unchanged), since local is worse than random for mislocalised answers.
