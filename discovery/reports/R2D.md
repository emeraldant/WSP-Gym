**Original query**: Test H7 (round_2/hypotheses.md): does the cascade (verify scale_rl sample 0, then search) still beat a rich, generic forward-pass search at the same evaluation budget? PRIMARY: test_trained, B=25, cascade(k=1 then rich search) vs rich search alone, random candidate order (seeded / exact expectation) and a weight-heuristic order, paired. Secondary: B in {10,50,100,full}, test_id, test_external, cascade with k=8, an "accept iff accuracy improved" verifier, a held-out-input check.

**Methodology**
- Scripts: `discovery/experiments/scripts/R2D_eval.py` (grid + evaluation), `R2D_analyze.py` (primary, budget table, k=8, cost), `R2D_extra.py` (improved-verifier, held-out check), `R2D_fig.py`. Outputs in `discovery/experiments/outputs/R2D/` (`analyze.out`, `extra.out`).
- Populations: all faulty episodes: test_trained n=403, test_id n=422, test_external n=415. Repair = recovery >= 0.95 (`env.score_answer` definition). I re-derived success for all 8 scale_rl samples per network from the forward passes and asserted agreement with the stored/scored `success` (0 mismatches). Planted inverse edit reproduces the clean accuracy on every episode.
- Rich generic op grid, built exactly as H7 lists, per network (mean N about 880 trained / 866 id / 681 external; duplicates and no-op candidates removed; no generator factors such as 1/3, 0.4, 2.5, 3, 10/3):
  sign flips (every W row, every W column, and every single-entry negation); swaps (W rows, W columns, biases, and W-row+bias pair, all pairs within a layer); scale by 0.5 and 2 (W rows and columns); zero (every W entry, every bias); bias add of +-{0.5,1,2} x row scale (mean |non-zero| of the row); rank-1 column add (every W column, vectors = unit vectors and top-2 left singular vectors of that W, amplitude +-{0.5,1,2} x median |W|). Judgement calls: entry negation counted as a "sign flip"; no bias scaling.
- Budget accounting: 1 evaluation per candidate, 1 per scale_rl answer verified (invalid answers and no-ops also cost 1). Cascade(k=1): evaluate sample 0; if it verifies (recovery >= 0.95 on the scoring inputs, i.e. the R1A verifier, equivalent to acc==1 on >99% of nets) stop, else the remaining B-1 evaluations go to rich search in the stated order. Rich alone gets B.
- Orders: (i) uniformly random, reported as the EXACT hypergeometric expectation per network (P(at least one of m repairs in first B of N)), checked by Monte Carlo with 50 seeded permutations (matches to 0.2 pt); (ii) weight-only heuristic = HistGradientBoosting on 17 weight-only candidate features (kind, layer, row/col norm ratios, bias/row-norm, sign statistics, rescale-invariant neuron-gain z-score, swap-pair cosine, entry z-score ...), trained ONLY on data/val.jsonl faulty episodes (236 nets, 205k candidates, 0.5% positive), candidates ranked by predicted probability (stable ties). No test labels used.
- Paired bootstrap over networks (10,000 resamples) for all CIs; diffs in percentage points.
- Held-out check: random half A / half B of each network's scoring inputs (seeded). Verifier = recovery >= 0.95 on the selection half using that half's own acc_clean/acc_faulty; the accepted repair is then scored on the other half; both directions averaged (<=0.6% of nets have undefined half-recovery and count as not found).
- Improved-verifier: accept iff accuracy on the shown inputs exceeds the faulty network's accuracy (no acc_clean). Two variants: first-improvement (stop at the first improving answer) and best-of-B (return the highest-accuracy answer evaluated if it improves). Random order simulated with 40 seeded permutations per network.

**Results**

Rich generic search quality (alone, full pool): repairs at least one candidate for 92.1% (test_trained), 91.9% (test_id), 92.3% (test_external) of faulty nets (median 4-5 repairing candidates per net; the generic grid cannot reach about 8%). Heuristic AUROC (per-net, test) 0.82 / 0.80 / 0.83; median rank of first repair under the heuristic 46 / 26 / 35 (of about 880). scale_rl sample 0 alone: 65.3 / 82.2 / 52.3%; best-of-8 77.2 / 90.5 / 65.1%.

**PRIMARY (test_trained, n=403 faulty, B=25, k=1)**

| order | rich search alone | cascade | cascade - rich (paired bootstrap 95% CI) |
|---|---|---|---|
| random (exact expectation) | 12.3% | 68.9% | **+56.6 [+52.3, +60.7]** |
| weight heuristic | 34.0% | 72.5% | **+38.5 [+33.5, +43.2]** |

(Monte Carlo with 50 seeds: rich 12.5, cascade 68.9, diff +56.4 [+52.1, +60.5].) H7 is supported under both orders. Most of the cascade's advantage at B=25 is simply scale_rl's first answer (65.3% alone): cascade minus model@1 is only +3.6 (random) / +7.2 (heuristic) pts. So at a matched budget of 25 passes, a rich generic search cannot touch the model's first guess; the search is what adds the last few points.

**Secondary: cascade with k=8 samples first** (raw cost 1 per sample, stop at first verified; distinct-answer caching gives nearly identical numbers). test_trained B=25: cascade8 78.8% (random) / 80.9% (heuristic) vs rich 12.3 / 34.0, diff +66.5 [+62.5, +70.2] / +46.9 [+41.9, +51.9]; cascade8 beats cascade1 by +9.9 [+7.2, +12.9] (random). B=100: 83.4 / 87.8 (+48.9, +24.3 vs rich). Full pool 98.5%. test_id B=25: 91.7 / 92.4 (+77.1 / +46.4); test_external B=25: 67.7 / 72.5 (+53.9 / +34.9). Best-of-8 verified alone (<=8 evals) already exceeds the rich heuristic search up to B=100 on test_trained (77.2 vs 63.5) and test_id (90.5 vs 68.5), and equals about the heuristic search at B=100 on test_external (65.1 vs 73.5, heuristic wins there).

**Secondary: "accept iff accuracy improved" verifier** (no acc_clean). Model sample 0 is accepted when it improves accuracy: it never misses a true repair, but false-accepts non-repairs: 13.6% (test_trained), 6.2% (test_id), 16.9% (test_external) of faulty nets. Consequence: with first-improvement acceptance the cascade at B=25 on test_trained is 66.0% (random) / 66.3% (heuristic) vs rich 4.6 / 17.4, diff +61.5 [+56.9, +65.8] / +48.9 [+43.7, +54.1]; the advantage of the cascade over rich search grows, because first-improvement acceptance stops rich search on non-repairing improvements (random rich falls from 12.3 to 4.6%). With best-of-B acceptance the numbers equal the oracle-verifier ones within 0.3 pts (cascade 68.8 / 72.5, rich 12.6 / 34.0). Conclusion: the headline does not depend on knowing acc_clean, but the model's own first answer cannot be fully trusted by an improvement-only verifier (it loses about 3 pts vs the recovery verifier through false accepts of the cascade's first stage).

**Secondary: held-out-input check** (select on one input half, judge on the other half, both directions averaged). test_trained B=25: rich alone finds 14.6% / 35.5% (random / heuristic) on the selection half and 11.9% / 32.9% on the held-out half (P(ok on other half | found) 0.82 / 0.93); cascade 69.7 / 73.3 found, 67.8 / 71.5 held-out (P(ok | found) 0.97), held-out diff +56.0 [+51.6, +60.1] / +38.6 [+33.6, +43.4]. Full-pool rich search: found 92.2%, held-out 83.3-84.4% (P(ok|found) 0.90-0.92), i.e. 8-9% of the repairs found by exhaustive rich search are spurious fits of the selection half (overfit to inputs, because the search tests about 880 candidates), while the model's own verified answers carry over almost always (0.95-0.97 under full cascade). test_id/test_external show the same pattern (full-pool P(ok|found) 0.93-0.96; cascade 0.97-0.99; held-out diffs at B=25 +70.4 / +43.0 and +44.1 / +28.8). Note the exhaustive tasks' halves are halves of the full input domain, so this check mainly measures selection noise.

**Interpretation**
- H7 holds: at a matched budget of 25 forward passes, cascade(k=1, then rich generic search) beats rich generic search alone by +57 pts (random order) or +39 pts (weight-heuristic order) on test_trained (CIs well away from 0), and across B, splits, orders and verifiers. This is the same qualitative result as R1A but now against a non-strawman: a rich 880-candidate generic search contains a repair for 92% of networks, yet needs about 300 random evaluations (150 with a val-trained heuristic) to find one, which makes any budget below about 100 far from enough.
- The result is still largely the model's first answer: cascade minus scale_rl@1 is only +3.6 / +7.2 pts at B=25 (test_trained). The informative statement is that the generic search is a weak and expensive rival at small budgets (12% / 34% at B=25) and a strong one at large budgets (92% full), while model proposals are a very high-precision prior. The cascade's lead shrinks with B (about +4 pts at full budget; heuristic order test_external +8.7 pts at B=100), so the claim is explicitly budget-dependent.
- Complementarity is real even against the rich search: the cascade at full budget (96.0 / 98.1 / 95.9%) beats the exhaustive rich search (92.1 / 91.9 / 92.3%) by +4.0 [+2.2, +6.0] on test_trained, since the model reaches repairs outside the generic grid (weight_corrupt copy-values, multi-neuron spurious directions).
- Heuristic ordering from val-only weight features doubles to triples the efficiency of rich search (AUROC about 0.8 on SGD networks despite being trained on compiled nets only), a cheap non-LLM weight-reading signal; it is the stronger rival and the one to quote as conservative.
- Caveats: (1) the generic grid is a judgement call; changing amplitudes (more bias steps, more column-add vectors) would raise the rich-search ceiling and lower its precision at fixed B in unknown ways; the grid cannot repair 8% of nets, which bounds rich-alone at full budget. (2) The heuristic is a single GBM, lightly tuned (no tuning on test), trained on compiled episodes only; a better learned ranker (cf. H4) could close more of the gap at small B. (3) The verifier uses acc_clean/acc_faulty (R1A convention); the improved-only verifier changes results by <=3 pts for the cascade but hurts rich search under first-improvement acceptance. (4) Costs count only evaluations of the shown network, not LLM inference. (5) Sample 0 of the stored k=8 rollouts is used as the single answer; all test splits were used once; no hyperparameters were chosen on them. (6) The exact random expectation treats the candidate list as a uniform random permutation after deduplication; Monte Carlo confirms it. (7) The held-out check is a split of the same input pool, not new inputs for non-exhaustive tasks.
- Suggested follow-ups: grid-sensitivity ablation of the rich pool (bias amplitude steps, drop column-add family); a learned ranker trained on trained-net episodes (H4 reader) as the search order; matched-compute comparison including LLM inference tokens.
