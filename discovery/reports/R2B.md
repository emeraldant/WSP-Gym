**Original query**: Test H5. (a) Frozen R1C solver (outputs/R1C/R1C_solver_FINAL.py + R1C_spec.py, unmodified) on fresh test_id-distribution episodes at seeds disjoint from data/, under default vs scale (0.1,10), noise 0.03, and higher-rate / unequal-weight pseudo-splits; n>=500 faulty per setting; repair and clean accuracy, paired. (b) Replay the generator from each seed for every episode of data/test_id.jsonl and data/test_trained.jsonl, assert bit-identical nets, then regress runs/final/scale_rl failure (and R1C solver failure) on the obfuscation factors with depth/fault/family controls (logistic, CIs).

**Methodology**
- Scripts: discovery/experiments/scripts/R2B_a_run.py, R2B_b_replay.py, R2B_analyze.py. Outputs: discovery/experiments/outputs/R2B/ (a_results_all.csv, a_summary.csv, b_replay.csv, b_regressions.csv, b_*_joined.csv). Figure: discovery/reports/figures/R2B_summary.png.
- (a) Config = `config_for("test_id", i)` (test_id header: 9 compiled families, 7 train faults, p_clean 0.18, variants weights / weights+failures), size alternating 0/1 by i exactly as splits.py does. Seeds 70,000,000 + i, i < 1000 (data/ maximum is 63,000,299; the reviewer's 41M pilot seeds overlap val_imperfect, mine do not). The same 1000 seeds are used in every setting, so family, variant and clean/faulty status are identical across settings (826 faulty / 174 clean each). The planted fault kind is only partly shared, because obfuscation draws shift the RNG stream (same fault kind in 84-86% of faulty episodes for scale/noise, 18-58% for pseudo-split). Differences are computed per seed, with a seed-level bootstrap (2000 resamples) for the CIs. Solver called exactly as in R1C_run.py "prompt" mode (spec parsed from the prompt, no params, no forward passes); score = env.score_answer. Zero generation errors, zero solver exceptions.
- Settings, via GymConfig only: scale=(0.1,10); noise=0.03 (note obfuscate halves sigma and retries when clean accuracy < 0.99, so realised noise can be lower); p_split. In obfuscate, p_split=0.5 gives a 25% split rate per distractor draw. Default split weights are already unequal (alpha ~ U(0.3, 0.7)). PRIMARY pseudo-split arm (fixed before running): p_split=2.0, which makes every distractor a split (measured splits/episode 1.27 default, 1.90 at p_split=1.0, 5.99 at p_split=2.0). Exploratory: p_split=1.0; p_split=2.0 plus extreme unequal weights (monkeypatch of nets.split_neuron remapping alpha to a in [0.05,0.15] or 1-a, a post-hoc-style function-preserving transform; verified max |f(split) - f(orig)| = 1.8e-15 on task.X over 40 random tasks x 3 alphas); a combined setting (all three).
- (b) Replay: obfuscate and train_network were re-implemented line for line with recording and monkeypatched into env/trained, then `make_episode(seed, config_for(split, i))` was called. The regenerated clean net, faulty net, family, variant, fault and shown failures were compared with the stored episode. Recorded per episode: per-layer #splits / #dead / #cancel pairs, normalised permutation displacement mean|perm[i]-i|/width, SD of the log-rescale draws (and max), noise rms and retry attempt. For SGD-trained nets there is no symmetry obfuscation, so the recorded factors are extra-neuron count, restart index and two post-hoc weight statistics (log-SD of row norms, max |w|).
- Regression: own IRLS logistic (statsmodels unavailable), Wald 95% CIs, factors standardised (OR per 1 SD), LR chi-square test for the whole factor block against the controls-only model. Controls: depth==3, size, variant, fault dummies (+ family dummies in the "full" model). Faulty episodes only (clean controls included in a robustness row). n_distract is exactly split + dead + 2*cancel, so it was dropped for collinearity (the three component counts are used). Everything in (b) is exploratory/associational (the primary was pre-registered as which factor, if any, predicts failure beyond depth/fault/family).

- The default fresh-seed repair (91.6%) is close to test_id (93.1%) and the reviewer's pilot (93.3%); clean accuracy 97.1% (n=174) is higher than the 88.6% in the reviewer pilot and 93.6% in R1C (differences are within sampling error for n=78-174 but note it).
- Prediction "drops >= 10 pts on at least 2 of 3": met by point estimate (scale -20.6, noise -10.2), but the noise CI [-12.8, -7.4] straddles the 10-pt line, so only the scale drop is clearly above threshold. Pseudo-splits, even at 4x the default count (6 vs 1.3 splits), do not hurt at all (CI excludes a 3-pt drop). The solver's cluster-by-direction step is therefore invariant to the split weights.
- Clean accuracy (false repairs) is the more fragile quantity: 97 -> 59 (scale), 62 (noise), 20 (combined). The solver does not abstain when residuals grow, it emits spurious ops.
- Scale hits harder on swap_out_cols (87 -> 52%) and scale_out_col (93 -> 67%), and across all families (equality 88 -> 61, minmax 86 -> 65, compare 82 -> 66). Noise 0.03 is family-specific: equality 88 -> 65, dnf 92 -> 74, parity 96 -> 74 while argmax/compare are unchanged. Size 1 is worse than size 0 in all perturbed settings.
- Paired discordance, faulty: scale lost 191 / gained 21; noise lost 109 / gained 25 (so the drops are real shifts of the same episodes, not just different faults, with the caveat of 84-86% fault-kind sharing).

(b) Replay and regression
- Bit-identical regeneration: test_id 500/500, test_trained 500/500 (clean net, faulty net, family, variant, fault, failure indices all equal). Match rate 100%.
- Failure rates (faulty only): scale_rl 17.1% on test_id (72/422), 33.3% on test_trained (134/403); R1C solver on test_id 6.9% (29/422).
- test_id, scale_rl failure, full controls (24 params): LR test of all six obfuscation factors chi2(6)=6.35, p=0.385. ORs per SD (95% CI): rescale spread 1.00 [0.73,1.35]; #splits 1.29 [0.90,1.84]; #dead 0.80 [0.55,1.18]; #cancel pairs 0.94 [0.62,1.42]; noise rms 1.41 [0.71,2.78]; permutation displacement 0.93 [0.69,1.25]. With light controls (no family dummies): block p=0.66. Including clean episodes: same (p=0.385).
- One factor at a time (full controls, 12 tests, no multiplicity correction): only #splits is nominally significant for scale_rl, OR 1.37 per SD [1.01, 1.86], p=0.044. Descriptively, scale_rl fails 12.5% with <=1 split (n=279), 26.7% with 2 (n=86), 24.6% with 3-7 (n=57), but part of this is shared with episode size (more splits in size-1 networks) and it disappears in the joint model. Treat as a weak lead, not a finding.
- test_id, R1C solver failure, full controls (only 29 failures, so wide CIs): block p=0.56; rescale spread OR 0.67 [0.42,1.06] (higher spread, if anything, fewer failures); #splits 1.10 [0.68,1.79]; noise 1.59 [0.71,3.79]; others ~1. The solver's in-distribution failures are not explained by the realised obfuscation either; they are better explained by fault x family (the control terms). Descriptively the solver fails 4.3% / 9.3% / 15.8% at <=1 / 2 / 3+ splits and 14.6% at 3+ cancel pairs (small n), but the single-factor LR tests give p=0.56 and p=0.99.
- test_trained, scale_rl failure: extra neurons OR 1.11 [0.65,1.89]; training restart used 0.98 [0.78,1.23]; row-norm log-SD 1.16 [0.82,1.65]; max |w| 1.21 [0.77,1.90]; block p=0.81 (full controls), 0.53 (light).
- Within the realised default test_id range the rescale spread is narrow (mean SD of log-c 0.36, max log|c| 0.69 = factor 2), and noise rms is 0.001-0.013, so (b) only tests the default intensity range; it cannot speak to scale (0.1,10) or noise 0.03, where the solver collapsed.

**Interpretation**
- The template shortcut is brittle along two axes that corrupt the numeric values it matches against (per-neuron rescale range and weight noise), and robust along the axis it was built for structurally (split/cancel/dead neurons, permutation). Its failure mode is spurious repairs on clean networks, which makes a no-abstention solver unsafe in any off-distribution regime. Combined harder obfuscation cuts it to 48% repair / 20% clean accuracy, i.e. below scale_rl's 83% on test_id, so the compiled-split "template beats model" result is a statement about the default noise/scale setting, not about structure obfuscation per se.
- On the model side, within the default obfuscation spread, none of the replayed obfuscation parameters predict scale_rl failures beyond fault/family/depth (joint test p=0.39 on test_id, p=0.81 on test_trained). The largest hint is more splits (OR ~1.3-1.4 per SD, CI touching 1), which is the one factor the solver is robust to. Model failures appear to be driven by task/fault identity rather than by obfuscation intensity, in this range. The model's sensitivity to extrapolated scale or noise was not tested (cannot query the model); the realised ranges are too narrow to detect it. A proper test needs scale_rl rollouts on episodes generated at scale (0.1,10) / noise 0.03.
- Caveats: pairing in (a) is exact on task/family/variant/clean status but fault kind differs in some episodes; one seed per episode; solver thresholds were tuned on the default setting; 12+ regression tests without correction; failure counts for the solver are small (29); noise retry halving means "noise 0.03" is an upper bound on realised noise. The extreme-alpha transform was applied inside obfuscate (before fault planting), not on the already-faulty net, so the fault stays in the canonical coordinates.
- Follow-ups: (1) run scale_rl (or the learned reader of R2A) on the scale/noise-hardened episodes to get the model's own sensitivity curve; (2) give the solver an abstain rule from alignment residuals and re-measure clean accuracy; (3) explore the noise x family interaction (equality/dnf/parity) and the swap_out_cols weakness under scale.
