**Original query**: Test H3 (template-alignment ceiling). Confirm what `render_prompt` shows; if the spec line determines the family parameters, rebuild the canonical net with `nets.build_task` (report prompt-only as primary, and quantify any leak of using `ep.task.params`). Write a forward-pass-free solver that aligns the shown net to the canonical one (undo per-neuron rescaling, match neurons, identify distractor/dead/cancelling/split neurons), locates the most inconsistent entry/row/column/bias, and emits a <=3-op DSL edit (or `[]`). Score with `env.score_answer`. PRIMARY: repair rate (and clean-control accuracy) of solver vs `scale_rl` on test_id faulty nets, paired bootstrap CI; also report test_larger, test_families, test_faults, test_trained, test_external; then ask whether scale_rl's per-fault success profile correlates with the solver's (template matcher?).

**Methodology**

*What the model sees (env.py `render_prompt`, read directly).* Intro text; `## Specification` = `task.input_desc`, `task.spec`, `task.output_desc`; `## Architecture` (layer widths and relu structure, so depth and width are known); `## Weights` (every W row and b rounded to 2 decimals); for the `weights+failures` variant (about 47% of nets) up to 8 failing inputs with expected and observed outputs; the task text. Not shown: family name, params, seed, clean net, inverse edit, fault fields. The solver uses only: shown weights, `input_desc` (input count and range, 0/1 or 0-9), `task.spec`, `family`, and the shown net's depth. It does not use failing inputs, `ep.clean`, `inverse_edit`, `fault`/`fault_info`, or `ep.task.params`. The family name is not printed in the prompt. It is recoverable from the spec text and I take it as given (a mild assumption; the spec templates are family-specific).

*Does the spec line determine the family params? Yes.* I wrote regex parsers for all 11 families (`scripts/R1C_spec.py`). Each rebuilds params from the spec string, `input_desc` and the layer count (for dnf the `deep` flag is the shown net having 3 layers). Each parsed task's `spec` string is asserted equal to the shown one. Fields the spec cannot fix (`dseed`, unused arith `lo`/`hi`) do not enter the canonical net. **Leak quantification**: for all 3,300 episodes (val 300 + six test splits x 500) the prompt-parsed canonical net is bit-identical (`MLP.equals`) to `build_task(family, ep.task.params)`. The leaky and prompt-only solver variants therefore give identical ops and identical scores on 100% of networks in every split (the "leak" is exactly zero). Everything below is the prompt-only version.

*Solver (`scripts/R1C_solver.py`, ~350 lines; frozen copy in outputs/R1C/R1C_solver_FINAL.py).* No network (shown or canonical) is ever evaluated on inputs. The only "semantic" computation is an interval range bound of each hidden pre-activation over the input box (`hi` from `input_desc`), used to recognise dead neurons.
1. Per hidden layer, collapse the previous layer's columns onto canonical neurons (positive per-neuron rescales `c_p` undone by the fitted row scale; split copies summed; so shown W is expressed in canonical coordinates).
2. Cluster shown neurons whose (row, bias) agree up to a positive scale: these are split copies and cancel pairs.
3. Hungarian-match clusters to canonical neurons with a robust row cost. The fit `row ~ c*(t, bt)` has signed `c` (negative = sign-flipped weights; the bias keeps `|c|`) and a capped per-entry loss. A column-direction term is added where meaningful.
4. Residual analysis. Row anomalies: flip, bias deviation, single-entry deviation (layer 1). Column anomalies: per canonical group, the residual of the collapsed column against the canonical column, at the matched next-layer rows. Cancel clusters (size >= 2, not matched to a canonical neuron) must sum to 0 unless certainly dead. Output rows: a swapped-row test for label swaps. "Stray" tests: a neuron whose row deviates from a cluster template (flip/bias/rowscale) is blamed when including it cancels the residual. "Revived dead neuron": a leftover neuron with pre-activation upper bound > 0.5.
5. Pick the strongest anomaly; emit it as 1 DSL op (set/scale/swap/add) or, for col/pair anomalies in one layer (swap_out_cols, spurious_direction), up to 3 ops; `[]` if nothing exceeds the threshold. Scored with `env.score_answer`.
Thresholds (noise tolerances 0.07/0.09, etc.) were set by looking at failures on **val** (300 nets, same distribution as test_id). The test splits were run once with the frozen solver. One robustness bug-fix was made afterwards: Hungarian padding when fewer clusters than canonical neurons (11 test_families nets crashed and were scored `[]`; no parameter change; effect +0.5pp on test_families, 0.792 -> 0.797; the other splits are unchanged). A stricter cluster tolerance (PAIR_RC 1.0/0.7) was tried on val and was worse, so it was not used.

*Statistics.* Paired bootstrap over networks (5,000 resamples, seed 0) for solver minus scale_rl; "repair rate" is on faulty nets, "clean accuracy" is the fraction of clean controls answered `[]`. scale_rl = `runs/final/scale_rl/<split>.jsonl`, one sample per net (direct-answer regime: effort 0, max_tokens 256, temperature 1).

**Interpretation**
- **Reading ceiling.** On compiled networks, once the spec is turned into the canonical net, weights alone (no forward pass, no failing inputs) suffice to repair 93% of test_id faulty nets with a hand-built solver tuned on 300 val nets. This is above scale_rl (83%; paired diff +10pp, CI [+6,+15]) and the gap widens out of distribution: test_larger +20pp, test_families +21pp, test_faults +55pp (the solver is fault-type agnostic by construction, so held-out `scale_in_row`/`spurious_direction` cost it little; scale_rl collapses to 20%). H3's first part is therefore supported strongly: **the compiled splits admit a pure template-alignment shortcut** that beats the trained model, and a 100% parse of the spec gives it the template with zero leak.
- **The shortcut does not exist off the compiled distribution.** On SGD-trained and sklearn nets the same solver scores 7-9% repair and about 1% clean accuracy. scale_rl keeps 67% and 51%. This confirms the second part of H3 and is the most important sanity statement about the gym: scale_rl's trained-net performance cannot come from template alignment, and compiled-split numbers alone overstate what is learned about weights in general.
- **Is scale_rl a template matcher?** Weak evidence either way. Coarse difficulty patterns line up (r=+0.77 over 22 fault x split cells, +0.52 over fault x family cells), but the search baseline's profile is uncorrelated or inverse. Cell correlations are driven by shared structure, such as faults that are easy to see in weights (flips, swaps) versus intrinsically ambiguous ones (spurious_direction, scale_in_row). At the network level the agreement is small (stratified phi about 0.1) compared to the model's own repeat-sample agreement of 0.85. The model does not fail on the same individual nets the solver fails on, and model success given solver success (0.85) is near the base rate (0.83). I would summarise this as "partially aligned in what is hard, not a template matcher in how it fails". Because the model is also better on trained nets (where no template exists), a mixture of local pattern reading is more plausible than alignment to the spec's canonical net. The model is clearly not exploiting the spec the way the solver does: on held-out families the solver (mux .98) beats the model (.63) by a wide margin.
- **Complementarity.** The solver and model are weakly dependent, and the union reaches 97% on test_id. A cascade (solver when its alignment residual is small, model otherwise) is cheap and, with a "template fits" gate to decide when to trust it, should beat either alone on compiled data. For trained nets the gate must reject the solver (alignment residual is large there).
- **Caveats.** (1) The solver is hand-engineered with knowledge of the gym's generator (what distractors, splits and rescales look like), tuned by inspecting val failures; it was frozen before test runs, but it encodes the symmetry group and the fault list. It is an upper bound on "reading with the spec", not a fair-play competitor of a model that must learn it. (2) scale_rl here is a single sample in the direct (no-reasoning, 256-token) regime, and it sees failing inputs in half the nets while the solver does not; reasoning-enabled models are not compared. (3) The solver's clean accuracy is lower (93.6% vs 100% on test_id; 82% vs 94% on test_larger) because noise-level inconsistencies or int-domain dead neurons that look alive trigger a false repair; the clean-control gap is significant on test_id and test_larger, not on test_families/test_faults. (4) The weaker regimes of the solver are depth-3 nets (79%), the held-out interval family (60%), and cases where a faulty neuron's fix is ambiguous with a distractor (e.g. a bias-shifted dead neuron that is revived is repaired only by a generic "set bias very negative"). (5) Correlation analyses are exploratory (not pre-registered), with small cell counts and unpaired fault x family cells reused across splits. (6) The family name is read from the episode, not the prompt, though it is recoverable from the spec wording.
- **Suggested follow-ups.** (a) Build the gated cascade and measure it on test_id/test_larger and on trained nets (gate = alignment residual). (b) Use the solver's alignment residual as a feature predicting which nets scale_rl fails on (does failure track near-ambiguity of the alignment, e.g. cluster conflations, rather than fault type). (c) Examine whether scale_rl's errors on test_faults (76% "right unit, wrong op") are fixable by the solver's column-residual add op. (d) Test how much of the solver's edge disappears when the spec is withheld, by learning the canonical net from the weights alone.
