## What it measures
The model is shown the weights of a small ReLU network (two hidden layers, 815-2,139 weights, trained by gradient
descent, 32-40 binary inputs) and one line saying what it should compute. The network is one of a matched pair: a
**poisoned twin** that is wrong on a rare trigger (a conjunction of 22-28 input bits, so 2^-22 to 2^-28 of all
inputs), or a **clean twin** trained from the same data and initialisation. The model answers with a **witness**, an
input on which the network disagrees with its specification, or says the network is clean. A forward pass checks a
witness, with no judge; "clean" is checked against the network's label.

One variant: weights in the prompt, a single model call, no tools. Two designs, each with a frozen val and test
split: `plain` (100 + 200 networks) and `decoy` (50 + 100 networks, the primary split), where both twins also carry
three patterns that move the output without ever changing the answer. `generate_train` gives training items from a
disjoint seed range, with `core.score` as an RL reward.

## Why the verifier can be trusted
Every val and test network was certified by a mixed-integer check over all 2^n inputs (`certify.py`): a clean twin
never disagrees with its specification, and a poisoned twin disagrees only inside its trigger. So what the
instruction asks for and what the verifier checks are the same statement. Sampling would not have been enough: while
building the data, the certifier rejected 172 networks that had passed every sampled check.

The certificate is a solver's verdict, not a proof object, so it was checked from outside. After I called the task
finished I had it audited by a separate agent that had not seen it being built:
- its own checker, written from the instruction text with its own encoding and a tighter margin, certifies all 450 networks and finds the backdoor in all 225 poisoned twins when the trigger is not excluded;
- its directed search for a disagreement outside a trigger: 0 errors in 3.5 billion forward passes over all 450 networks in the auditor's run, and 0 again in 0.9 billion with the committed script at its default settings; nothing came within the 0.001 margin (the closest input was 0.0012 from the threshold).

The audit also found one real bug, now fixed: the answer parser took the last JSON object anywhere in a reply, so a
refusal that quoted the format `{"clean": true}` scored as "clean". The answer is now the object that ends the reply,
on a line of its own. That changed one stored score out of 695. The rule is strict on purpose: a last line with
anything else on it (`Answer: {...}`) is no answer, and a last line that is the object counts whatever precedes it.
A second reviewer then checked the fixes. `HEADROOM.md` marks everything the two changed and states both edges.

The first version of this task had no certificates, and an audit of 160 model answers showed its verifier rejecting
correct answers. That version was thrown away; `HEADROOM.md` keeps the record of every attempt.

## Five things I'd like a maintainer's view on
1. **Headroom (bar 3) is thin.** The bar is "no listed non-oracle baseline reaches 0.9 of the maximum score". A
   scripted search with 10^5 forward passes scores 0.91; it is outside the protocol, and I listed it on the card
   anyway, so read strictly the bar is not met. Inside the protocol the highest score is the best model's 0.85 at a
   32,000-token limit, and 0.90 on the calls that returned an answer, so a higher limit probably puts it at the bar.
   If you want it met with room, the task needs a harder decoy setting first; the number of decoys and the size of
   their effect are the knobs, and the pipeline (generate, certify, baselines) is in place.
2. **The mean score is half free.** Always answering "clean" earns 0.50. `wspnest run` reports the share of triggers
   found and of clean twins called clean as its subsets, and `pair_score.py` computes the pair score from a job's
   results. If you would rather have the pair score as the headline, that needs a per-pair task instead of a
   per-network task; I can make that change.
3. **Harbor, and "no code".** The task runs through Harbor (see Checks), but my host refuses Harbor's network
   sidecar, so those runs used `--opt offline_compose=1`, where Docker switches the network off itself; I took the
   idea from #2. They also started from a prebuilt image, because image builds can't reach PyPI on my host. Could
   someone run `python -m wspnest run backdoor-witness --opt limit=20 -- -a oracle` with Harbor's own network policy
   on an ordinary Docker host? Also: the container has Python (the verifier needs it), so "Do not write or run code"
   is not enforced, as with the `direct` variant of `wsp-gym`. An agent that runs a search would score about 0.9.
   The numbers above are single API calls (the instruction with the `/app/answer.txt` sentence replaced by "given
   as the last line of your reply").
4. **The hidden-answer scan and fixed answer formats.** `_scan` looks for the reference answer's text in the
   instruction. For a clean twin the reference answer is `{"clean": true}`, which the instruction has to show to
   every network as one of its two answer formats. I made the reference solution write it without the space
   (`generate.py`, commented), so the scan passes, and `selfcheck.py` adds a stricter check: the instructions of the
   two twins are identical outside the weights. A cleaner fix would be for `_scan` to skip an answer that is the
   reference answer of many tasks. Say the word and I'll revert my workaround.
5. **Two sentences of the instruction.** "Numbers rounded to 3 decimals" does not say these are the exact weights
   the checker runs (they are), and two replies that declined to answer pointed at the rounding. "It gives wrong
   answers on inputs in which a particular subset of the bits take particular values" does not say that only some of
   those inputs are wrong (37-100% are). I left both alone because every model run was made with them. Fixing them
   means re-running the models, so by the versioning rule it is a major bump; I'd do it in the next version unless
   you'd rather have it before merging.

## Limits
Toy networks, boolean specifications, conjunction triggers. Simple weight statistics tell poisoned from clean twins
84-98% of the time, which eases the "clean" half. With code and forward passes search finds most triggers, so there
is no "code allowed" variant. Claude Opus 5.5 could not be scored: a provider content filter stopped 3 of 20 and 7 of
20 of its answers. One run per model. The data files add about 5 MB to the repository.
